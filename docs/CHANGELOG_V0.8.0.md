# 更新日志 v0.8.0 - 增强与清洗 (Augmentation)

> **发布日期**: 2026年2月 (预计)
> **版本主题**: AI 驱动的数据增强与成本可控的智能清洗。

本版本引入了“非破坏性增强 (Non-Destructive Augmentation)”架构，赋予用户通过 AI 将非结构化文本转化为结构化维度，并自动生成高阶时间分析指标的能力，同时建立了稳健的 Token 成本审计体系。

---

## 🚀 核心新特性

### 1. 🏗️ 伴生数据架构 (Sidecar Architecture)
为了支持对原始数据的“增强”而不破坏源文件，我们构建了全新的底层存储机制：
*   **全局行 ID (_ws_row_id)**：所有数据表现在均具备不可变的全局唯一行标识，基于 DuckDB Sequence 技术实现，确保数据血缘的绝对可靠。
*   **伴生表 (Sidecar Tables)**：AI 生成的清洗结果、标签提取等数据存储在独立的扩展表中。
*   **动态视图 (Dynamic Views)**：用户始终通过实时拼合的视图操作数据，实现“原始数据只读，增强数据叠加”的安全模式。
*   **级联清理**：删除主表时，自动清理关联的伴生表与序列资源，防止垃圾数据残留。

### 2. 💰 Token 审计与预算 (Token Audit System)
针对 AI 批处理可能带来的成本激增，我们构建了三层防护体系：
*   **事前预估**：在执行大规模任务前，自动计算预估费用并弹窗预警。
*   **事中熔断**：实时监控批处理任务的 Token 消耗，超支自动暂停。
*   **混合审计模型**：支持全局预算控制（保护 API Key）与项目级明细审计（数据资产留痕）。

### 3. ✨ 基础设施准备
*   **AI 批处理管道**：为即将到来的“智能字段提取”和“自动清洗”功能铺平了道路。
*   **数据兼容性升级**：旧版本项目在打开时将自动迁移至新的 Sequence 架构。
